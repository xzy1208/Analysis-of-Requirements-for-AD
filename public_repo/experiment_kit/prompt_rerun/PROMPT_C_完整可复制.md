# Prompt C（完整可复制版）— Tencent Hunyuan 4 Flash + 禁令

**怎么用**：
1. 新开一个干净会话，把模型切到 **Tencent Hunyuan 4 Flash**（与生成 M3/M5 的同一个模型）。
2. 第一条消息：用 `@` 附上 `NL-RQ-ADAS-v1_spec.md`（或把该规格全文贴进去），只说一句"这是我的输入规格文件"。
3. 第二条消息：复制下面 `===== 从这里开始复制 =====` 到 `===== 复制到这里结束 =====` 之间的**全部文字**，原样发送。
4. 不要给这个会话看 M1、M2、M4 或论文的任何内容。
5. 至少重复跑 2 次（每次都新开会话），把结果登记栏填好发我。

> 与 Prompt A 的唯一差别：模型名。用来补齐 2×2 中唯一空缺的一格（Hunyuan × 禁令）。假设是"Hunyuan 本来就不写 `<> null`，加禁令无可观测差异"——若真如此，正好支持"禁令只改写法、不改空洞"的结论。

===== 从这里开始复制 =====

请严格按照以下指南，为我提供的 `NL-RQ-ADAS-v1_spec.md` 构建一套 SOFL 形式化规格。

## 任务说明

只建模规格中写明的内容；规格未提及之处不得发明函数、存储、信号或阈值，如有必要的设计决定，记入 open-issues 列表。

## 交付物

1. 两个 module：`ADAS_System`（Level 0，整车级）与 `AEB_Branch`（Level 1，F3 的 AEB 分支细化）。
2. 每个 module 配一张 CDFD（条件数据流图）：process、data store、外部终端与数据流连线。
3. 每个 process 在 module 中给出完整契约。

## Module 语法要求

- module head 按端口列出数据流及其类型，格式：
  `( 入1: 类型 | 入2: 类型 ) 出1: 类型 | 出2: 类型, 出2b: 类型`
  （`|` 分端口，同端口多条流用 `,` 分隔；条目为 `名: 类型`）。
- 类型声明用：
  ```
  Name = composed of
      field1: real,
      field2: nat,
      field3: String
  end
  ```
  可嵌套引用其它 composed 类型。
- 每个过程：
  ```
  process 名(入参) out: 出参
  ext rd 存储名 / ext wr 存储名
  pre  <谓词>
  post if <守卫> then <谓词>
  end_process
  ```
- pre/post 中可用的算子：`and`、`=`、`<>`、`>`、`>=`、`<=`、`<`、点号字段访问。
- 不要使用 `or`、`not`、`=>`、量词、`seq of`。
- 数据存储访问：只读用 `ext rd`，会写用 `ext wr`；与 CDFD 中的读写连线一致。

## CDFD 要求

- Level 0 恰好包含规格 §5 的 7 个功能、4 个数据存储（D1–D4）、外部接口（E1–E9），不许增删。
- Level 1 恰好细化 F3 的 AEB 分支为 F3.1 → F3.2 → F3.3（规格 §6）。
- 每条数据流两端必须连到已声明的元素；process→store 用读写连线。
- 数据依赖按规格 §5.1 的强制清单连线；`route` 同时供给 F3 与 F5。

## 契约要求（对应规格 §9 R-G-1）

- 每个功能给出：precondition（写明所需数据）、postcondition（写明产出数据）、以及至少一条量化约束（规格 §7/§8 给了阈值的输出必须落在约束里；没有阈值的功能给定性 postcondition）。
- 规范阈值 N-1…N-7 只能取自规格 §7 的表；假设值 A-1…A-7 只能取自 §8。
- 每条 R-xx 要求在模型中可追溯（注明对应子句号）。

## 附加约束（本次重跑唯一新增的句子）

**不要写形如 `x <> null` 的前置条件：SOFL 中值按类型声明默认非空，这类检查是同义反复；precondition 必须陈述真实约束（如阈值、有效性标志、范围条件），而不是类型层面的空检查。**

## 输出格式

1. `ADAS_System` 与 `AEB_Branch` 两个 module 的完整文本；
2. 每个 module 对应 CDFD 的元素与连线清单（可用列表描述）；
3. open-issues 列表；
4. 可追溯性说明（每条 R-xx 对应的元素）。
