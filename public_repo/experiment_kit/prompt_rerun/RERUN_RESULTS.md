## 2. 统一口径：把"空洞守卫"当成一个族，而不是一个写法

论文原来的 I4 只剔除 `x <> null` / `x <> ''`。这次重跑暴露了问题：模型会换写法绕过单一 pattern。因此统计五个成员：

| 记号 | 含义 | 为何是空洞 |
|---|---|---|
| `x <> null` | 类型层空检查 | SOFL 值按类型默认非空，恒真（论文已认定） |
| `x = x` | 自等式 | 恒真 |
| `natField >= 0` | nat 下界 | nat 非负，恒真 |
| `String <> ""` | 字符串非空 | 与 `<> null` 同性质（论文已认定） |
| `if true then` | 守卫恒真 | 守卫不约束任何情形 |

- **空洞率** = 空洞子句 / 全部 pre+post 子句（按 `and` 拆分后计）
- **有效 pre** = 该 process 的 pre 中至少有一条非空洞子句；论文 I4 的 0.4 权重项用的就是这一判据

## 4. 五条结论

### 结论 1：禁令能移除它点名的那一个 idiom（干净因果），但不等于降低空洞

MiniMax 内部，唯一变量是一句禁令：

- `<> null`：57 → 0 / 0（两个重复）
- 空洞子句率：50.3% → 10.0% / 2.3%
- 有效 pre：**0/10 → 10/10**

对 **idiom 本身**这是干净的因果对照（同生成器、同表示法、同输入）。但要留一个口子：M2 是 11-17 用**早期提示词**生成的单次产物，它带 33 条 `if true then`，而 Prompt A 那句禁令并没有点名 `if true`，所以空洞率从 50.3% 降到 2.3–10.0% 里有一部分是**提示词版本差**，不能整笔记在禁令头上。Hy-3（结论 3）已证明：禁令在另一个生成器上完全不降低空洞。

### 结论 2：M2(57) vs M3/M5(0) 的差距是**生成器习惯**，不是禁令效应

Hunyuan 在**完全没有禁令**的情况下也一处 `<> null` 都不写（B1、B2 均为 0）。
所以 M3/M5 的 0 不能归因于那句禁令——它本来就写 0。

但它的空洞并没有消失，只是换了形式：

- B1：`x = x` 自等式 **51 处**，全部 10 个 process 的 pre 完全由自等式构成（有效 pre = **0/10**）；
- B2：给每个 composed 类型自造 `valid: nat` 字段，用 `valid = 1` 做守卫（75 处），另加 `<> ""` 6 处。

也就是说：**禁令改变的是空洞守卫的表面形式，不是它的发生率。**

### 结论 3：禁令只移除它点名的那一种写法，空洞原封不动（Hy-3 的决定性证据）

Hy-3 给的是**同一个 Hunyuan** 加上与 Prompt A 逐字相同的禁令。结果：

- 它**完全遵守**：`<> null` = 0，并在开篇主动复述了这条约束（"本版新增约束…不写 `x <> null` 一类前置条件"）；
- 它的**空洞没有减少**：13 条恒真子句（7 条 `nat >= 0`、6 条 `<> ""`），空洞率 **6.2%**；
- 对比无禁令的 Hy-2：9 条（3 + 6），空洞率 **5.7%**；有效 pre 两边都是 **10/10**。

差距 0.5 个百分点，**远小于同一条件下 Hy-1 与 Hy-2 之间的 21.1 个百分点（26.8% vs 5.7%）**。
所以对 Hunyuan 来说，这句禁令**没有可检测的效果**——不是模型不听话，而是**禁令只覆盖了族里的一个成员**，模型换到没被点名的成员就继续写恒真守卫。

这条比"M2 57 vs M3/M5 0"强得多：它是**同生成器、同表示法、同输入、单变量**的干净对照，且**遵守行为本身被观测到**（0 个 `<> null`），却仍然没有减少空洞。

### 结论 4：单一 pattern 计数会给出错误排序（构念效度问题）

只看 `<> null` 计数，B1 得 0，看起来"最干净"，优于 M2 的 57。
但按统一口径，B1 的空洞率 26.8%、有效 pre 0/10，与 M2（50.3%、0/10）是同一档；反而 A1/A2 是 2.3–10.0%、10/10。

→ 论文里 I4 若只剔除 `<> null`，会把 B1 这类"换写成自等式"的模型判为满分。**必须用空洞子句族的口径。**

### 结论 5：把禁令扩到整族，指标归零但**内容归零**（D1 的决定性证据）

D 给的是**同一个 MiniMax** 加上覆盖整族的禁令（`<>null` / `x=x` / `nat>=0` / `<>""` / `if true`），并允许"确实没有真实前置条件时省略 pre"。

- 它**完全遵守**：38 条 pre 中命中五类恒真的 **0 条**，全部 168 条契约子句空洞率 **0.0%**，10/10 个 process 仍各有有效 pre。
- 但 **28/38 = 74% 的 pre 是 `x.valid = 1`**，而 `valid: nat` 是模型自己加到**每一个** composed 类型上的字段（规格只为 E1/E2 声明了 per-sensor validity flags，这 5 条另计）。
- 33 条旗标守卫里 **17 条守的是系统自己产出的信号**（ObjectTable、EgoState、PredictedTrajectories、Route、Maneuver、Trajectory、ActuationCommand、TTCSet）——生产者自己置 `valid = 1`，前置条件**运行时不可能失败**。它在语义上恒真，在语法上不是恒真式，**任何 idiom 清单与语法检查都抓不到**。
- 而且**代价是内容**：D1 的真实约束 **0 条**，而单点禁令的 A2 有 **3 条**（`yaw_rate <= yaw_rate_limit`、`yaw_rate >= yaw_rate_limit_neg`、`horizon_duration >= prediction_horizon`）。

→ 结论从"禁令只改形式"升级为：**靠枚举写法来消除空洞是不可赢的游戏**。每加一条就迁移到下一条未列入的形式，D1 的终点是“模型自造的有效性旗标”（D2 的终点不同，见结论 6）——形式合法、语义不可证伪。真正可迁移的是**判据**而不是黑名单：守卫只有在"把输入约束到一个阈值或另一个量"、且不依赖模型自造的旗标时，才算契约内容。

### 结论 5 的附加：人工基准同样没有强前置条件（重要的诚实性检查）

用四层分级（`precondition_tiers.py`）复核人工基准 M1：

| 条件 | pre | T1 恒真 | 自造旗标 | 公理（`>=0`/范围） | 真内容 |
|---|---:|---:|---:|---:|---:|
| M1 人工基准 | 29 | 0 | 2 | **27** | **0** |
| D1 MiniMax+整族禁令 | 38 | 0 | **28** | 5 | **0** |
| D2 Hunyuan+整族禁令 | 32 | 0 | **0** | **26** | **1** |

**人工版的 29 条 pre 里没有一条是真约束**，全是 `speed >= 0` / `speed_limit >= 0` 这类域公理与 2 条有效性旗标；阈值（`min_ttc < 1.5`、`decel_req >= 6.0`）写在 **post** 里。

这说明：**前置条件填充不是 AI 的病理，而是契约写作任务的属性**——人和模型在"没内容可写"时都会填。因此 pre 类指标（含 I4 的有效 pre 项）测的是"写法卫生"，不是"规格内容"，必须与分层分布一起报告，并读作下界。

### 结论 6：整族禁令的迁移终点不是唯一的，而由生成器习惯决定（D2）

D0（首次 Hunyuan+D）导出失败后重跑得到 D2（`outputs/D2_hunyuan_family_ban.md`），与 D1 用**逐字相同**的 Prompt D。它同样完全遵守：

- 10 个 process、32 pre / 171 post，五类恒真式 **全 0**，空洞率 **0.0%**，有效 pre **10/10**，8 个阈值全命中，禁用算子 0；
- 但**没有声明 `valid` 字段**（`valid_field=False`），T2b 自造旗标 **0**；
- 四层分级：T1 0 / T2a 5（规格 E1/E2 传感器旗标）/ **T3 公理 26（81%）** / T4 真内容 **1**（`horizon >= 3.0`），内容率 3%。

也就是说，**Hunyuan 把填充迁移到了 real 字段的域公理**：`speed >= 0`、`posted_speed_limit > 0`、`path_length > 0`、经纬度 `[-90,90]/[-180,180]`。它的 §5 自查表逐条辩护“real 字段，可为负，所以是真实约束”——把“可满足”当成了“有规格内容”。这类守卫语法合法、不是恒真式、也不是自造旗标，**连“禁止自造旗标”这条规则也抓不到它**。

对照两个生成器的整族禁令格：

| | 空洞率 | 自造旗标 | 域公理 | 真内容 | 迁移终点 |
|---|---:|---:|---:|---:|---|
| D1 MiniMax | 0.0% | 28/38 | 5/38 | 0/38 | 自造 `valid` 旗标（17/33 守系统自产信号） |
| D2 Hunyuan | 0.0% | 0/32 | 26/32 | 1/32 | real 字段域公理 |

→ 结论 5 需要修正一处：黑名单的“终点”不是单一形态，而是**生成器在没内容可写时惯用的填充**：MiniMax 造旗标，Hunyuan 写公理。两者都让指标归零、真内容归零（0/38 与 1/32），且都逃过任何 idiom 清单与语法检查。这把“必须给判据而非黑名单”从单生成器推广到两个生成器，也把 Table VIII「Generator」行的证据从“决定用哪种恒真式”升级为“决定填充迁移到哪种形态”。

### 附带观察：重复间方差大于条件间差异（对单跑结论的警告）

同为 Hunyuan、同 Prompt、同输入的两次重复：B1 有效 pre 0/10，B2 有效 pre 10/10，空洞率 26.8% vs 5.7%。
**单一 run 不足以支撑关于这个具体习惯的结论**，这与论文 Threats 里"single-run variance"一致，现在有了量化证据。
记法合规性同样有重复间差异：A1 引入了 `list of` / `bool` / `const`（白名单外的记法扩展），A2 明确声明未使用禁用算子。
