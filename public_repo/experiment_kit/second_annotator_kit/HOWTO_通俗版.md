# 第二标注者：具体怎么做（通俗版）

## 一句话版本

找一位同学，把 `annotator_workbook.md` 和 `annotator_form.json` 发给他，
他填完发回来，你跑一条命令，就得到论文要用的 κ。

**耗时：约 30–45 分钟。**

---

## 为什么不复杂

你可能会以为"第二标注者"意味着让另一个人把 44 条需求全部重判一遍——**不是**。

我们统计过 44 条原子需求的判别力：

| 集合 | 条数 | 能区分模型吗 |
|---|---:|---|
| Level 0 全部 | 31 | ❌ 所有模型得分都恒为 1（结构由规格强制规定） |
| Level 1 的 AEB-1..6、TH-2、TH-7 | 8 | ❌ 同样恒为 1 |
| **Level 1 的 TH-1/3/4/5/6** | **5** | ✅ **全部差异都在这里** |

也就是说，**只有 5 条需求值得让第二个人判**。剩下的 39 条怎么标都不会有分歧，
标了也是浪费同学的时间。

这 5 条 × 6 个模型 = **30 个判断**，再加上 24 个"对照"判断
（用来检查同学是不是对某类模型一律给"已覆盖"），总共 **54 个判断**。

---

## 三步走

### 第 1 步：找人

**谁合适**：同学即可，不需要是需求工程专家。最好是研究生/本科生，
能读懂一点英文技术文档、看懂条件表达式。

**唯一硬要求**：**不能看过论文正文、不能看过你的标注结果**。
他必须是独立判断，否则 κ 就没意义了。

**怎么跟他说**（可以直接转发）：

> 帮我一个忙，30 分钟。我有一批需求，需要你独立判断"某个模型有没有写到它"。
> 我会给你一个手册，里面每张卡都列好了要看的候选条款，你只需要打 1 / 0.5 / 0
> 并写一句理由。不要看论文正文，也不要问我"标准答案是什么"——
> 我要的是你的独立判断，我自己也是这么标的，我们要比对一致程度。

### 第 2 步：发材料

**先跑这一步生成交付目录**：

```bash
python experiment_kit/second_annotator_kit/build_handover.py
```

它会生成 `experiment_kit/second_annotator_kit/handover/`，里面有 5 个文件：

| 文件 | 作用 |
|---|---|
| `给标注者的说明.md` | **给他看的**：做什么、怎么填、纪律要求 |
| `annotator_workbook.md` | **手册**：评分规则、模型说明、54 张判定卡（每张都附了候选条款） |
| `annotator_form.json` | **填答表**：他在 `label` 填分数、在 `evidence` 写理由 |
| `填写示例.json` | 只示范格式，不是真实判断 |
| `MANIFEST.txt` | 文件清单与 sha256，用来核对材料有没有传丢 |

> ⚠️ **只发 `handover/` 这个目录**。不要把 `second_annotator_kit/` 整个目录发出去 ——
> 里面的 `labelling_template_discriminating.json` 含 `primary_label`（就是答案）。
> `build_handover.py` 会在生成后自动做泄题扫描，不干净它会直接报错、不产出目录。

**关键设计**：每张判定卡已经把该模型里与这条需求相关的条款**自动摘好了**，
按相关度排序。同学不需要在几千行模型文件里翻找——他看 3–16 行候选条款就能判断。

候选条款的排序不是"最像的排前面"，而是**按模型自己声明的可信度**排：

1. **模型自称实现了这条需求**的追溯行（`[N-4] …`）/ 文档表格行（`| N-4 | … |`）——
   这类最可信，因为是模型自己写的追溯说明；
2. 数值/字段名直接对上的条款；
3. 语义相关但没有具体数值的条款。

每条需求都标了它在规格里的编号（如 `N-4`、`F3.1`）。**模型在追溯表里写上这个编号，
就等于声明"我实现了这条"** —— 这条规则也写进了手册，让同学据此判断。

> 手册里已经有 54 张卡、每张都附好了候选条款。**正常情况下不需要打开原始模型**，
> 只有当卡片上的候选明显跑题、而你怀疑模型里其实有内容时才翻原件
> （手册第四节列了每个模型对应的原始产物路径）。

**必须提醒他的纪律**（手册里也写了）：

- 不要看 `coverage_manual.json`（那是你的答案）
- 提问在开始前一次问完
- 拿不准就照第一反应填，并在 evidence 里写明理由

### 第 3 步：收回来算 + 改论文

他填完，把 `annotator_form.json` 存成 `annotator_form_filled.json`，然后**一条命令走完全流程**：

```bash
# 先演练，不改论文
python experiment_kit/second_annotator_kit/finish_second_rater.py annotator_form_filled.json

# 确认无误后真正写入
python experiment_kit/second_annotator_kit/finish_second_rater.py annotator_form_filled.json --apply
```

它串起三步：

1. **算 κ** → 判别力集的未加权 κ 与线性加权 κ（论文要报的数字）、对照集一致率、
   逐条分歧清单；
2. **回填论文** → 中英两版共六处：
   §V-A2（表 IV-C 讨论段）、§VII Threat 4、附录产物表。
   每处替换都断言命中数恰为 1，命中数不符就报错、**不写文件**；
3. **引用完整性复核** → 改稿后必查，两版都应为 37/37 全绿。

措辞会随实测数值自动调整：

| 实测 κ | 论文里怎么写 |
|---|---|
| ≥ 0.80 | 高度一致（substantial） |
| 0.60 – 0.80 | 中等至高度一致 |
| 0.40 – 0.60 | 中等一致 |
| < 0.40 | 有限一致；并声明 Level-1 结论仍以敏感性分析而非一致率为依据 |

对照集一致率的措辞也随数值变：≥90% 说"未见系统性偏袒"，
70–90% 说"表现为轻度偏严"，<70% 明说第二标注者在明确成立的条目上亦系统性偏严。
**不会在对照集一致率低的时候还写"未见系统性偏袒"** —— 那会是假话。

## 论文里怎么写

`finalize_second_rater.py` 生成的 `paper_patch.md` 里已经写好了句子。
你把它粘到 **Threat 4** 里，替换掉现在这段：

> ~~No second rater was recruited, so no inter-rater agreement statistic exists for
> this baseline~~ → 换成 κ 的实际数字。

> ⚠️ **不用手工粘。** `finish_second_rater.py --apply` 会自动改中英两版共六处：
> §V-A2、§VII Threat 4、附录产物表。手工改容易漏改中文版，或把两个 κ 混为一谈。

**两个 κ 别搞混**（论文里会并列出现）：

| | 是什么 | 来自 |
|---|---|---|
| **κ_obs** | 实测：第二标注者与主标注的真实一致性 | 标注者填的表 |
| **κ_bound = 0.608 / 0.582** | 稳健性上界：把最严格口径的打标代入后的理论一致性 | 主标注推算，**不是实测** |

脚本会把这两者的区别明确写出来，不用你操心。

**如果 κ 很高（≥0.8）**：说明你的标注是稳定的，Threat 4 从"未处理的缺陷"
变成"已量化的方法学局限"——审稿人的问题被回答了。

**如果 κ 一般（0.4–0.8）**：也正常，重点是看分歧清单。如果分歧都集中在
TH-3/TH-4（就是"推导值算不算覆盖"那一条规则），那正好印证了表 IV-C 的敏感性分析：
那个判断有解释空间，但结论不依赖它。脚本会把这句写进 Threat 4。

**如果 κ 很低（<0.4）**：说明规则没讲清楚。这时候先看分歧清单——
多半是某条规则的解释有歧义，把规则补进手册，让同学重判那几个点就行，
不用全部重来。脚本会自动在 Threat 4 里声明"Level-1 结论仍以敏感性分析而非一致率为依据"。

**如果对照集一致率也很低**：说明第二标注者在明确成立的条目上就偏严。
这时候判别力集的低 κ 有一部分是整体偏移造成的，脚本会把这一点写清楚，
读的时候别把它当成"逐条判断分歧"。

## 常见问题

### 同学问"我找不到相关条款"怎么办

手册里每张卡都标了模型对应的原始产物路径。让他直接翻那个文件。
如果确实是模型没写（比如 M1 在 TH-3/TH-5 上确实没写），那答案就是 0，
**这本身就是有效结果**。

### 手册会不会泄题

不会，而且是**机器检查过**的：

- `annotator_form.json` 里**没有** `primary_label` 字段，所有 `label` 初始为空；
- `build_handover.py` 生成 `handover/` 后会扫描一遍，出现任何答案痕迹就报错、不产出目录；
- 交付目录里只有 5 个文件，**没有** `labelling_template_discriminating.json`
  （那个文件含 `primary_label`，是答案本身）——所以只发 `handover/`，别发整个目录。

### 能不能让同学直接填 markdown 而不是 json

可以。让他在 `annotator_workbook.md` 的每张卡上填 `label` 和 `evidence`，
然后你把这些抄进 `annotator_form.json`。不过直接填 JSON 更省事，
用 VS Code 或任意文本编辑器都能改。

### 我只有 15 分钟

那就只做判别力集的 30 个判断，跳过对照集。
`finalize` 脚本会在判别力集上算 κ，对照集一致率显示为空。

---

## 一句话总结

**5 条需求、6 个模型、30 个判断、约 40 分钟。**
手册已经把候选条款摘好了，同学只需要打三个档并写一句理由。
