# 盲评审包 —— 使用说明

## 这个包是做什么的

让一个**全新会话**对四个车载 ADAS 需求模型做独立缺陷评审。

**本次指定模型：DeepSeek-v4-pro**（与评审者 B 相同）。这是刻意设计——不是换模型，而是换上下文：

- 评审者 B 的旧三轮（`review_roundB1/B2/B3.json`）：DeepSeek 在**同一会话**中、读过评审者 A（Hunyuan Hy）结果后做出 → **污染上下文**
- 本次新三轮（`review_roundC1/C2/C3.json`）：DeepSeek 在**全新会话**中、只看规格+脏模型做出 → **干净上下文**

两者模型相同、唯一变量是上下文，差值即为"会话污染对 AI 评审的影响大小"，闭合论文 VI-5 的效度缺口。
与旧 B 的锚定轮合起来，构成同一模型的三级上下文阶梯：**干净 → 污染 → 明确锚定**。

## 操作步骤（一个会话，连续三轮）

> 与 A（Hy）和 B（DeepSeek）保持同一口径：它们都是**同一会话内连续三轮**评审
> （产出时间戳间隔 1–2 分钟 / 同一分钟可证）。为控制变量，本轮也用一个会话连做三轮，
> 这样 C vs B 的唯一差异才是"是否读过 A 的结果"（上下文污染），而不是会话结构。

1. **新开一个会话**（不要继承任何历史对话——当前这个会话聊过 A/B 结果，不能用），
   模型切换为 **DeepSeek-v4-pro**（与评审者 B 相同）。
2. 把本包中标记为 ✅ 的文件全部作为附件/上下文上传：
   - `NL-RQ-ADAS-v1_需求规格.md`
   - `MES_schema.md`
   - `review_input_M1_L0.md`、`review_input_M3_L0.md`、`review_input_M4_L0.md`、`review_input_M5_L1.md`
   - `raw_M1_L0.json`、`raw_M3_L0.json`、`raw_M4_L0.json`、`raw_M5_L1.json`
3. 打开 `复制给新会话的提示词.md`，**整文件内容复制**，把 `{{N}}` 换成 `1`，粘贴发送；
   把输出存为 `review_roundC1.json`。
4. **在同一个会话里**，把 `{{N}}` 换成 `2` 再发一次，输出存 `review_roundC2.json`；
   再换成 `3` 发一次，输出存 `review_roundC3.json`。

三轮在同一个会话里连续完成，得到 `review_roundC1/C2/C3.json`。

## 盲性纪律（务必遵守）

- ❌ **不要**把工程目录里的以下文件提供给评审模型：
  `defect_manifest.json`（缺陷真值）、任何 `review_*.json`（含 A/B 结果）、
  `cross_reviewer_results.json`、`defect_injection_results.json`、
  `paper_draft_v1.md` 及其中文翻译版、任何 `cross_reviewer_analysis.py`。
- ❌ **不要**把 A/B 的任何评审结论用聊天的方式告诉这个新会话（包括"上一轮评审发现了什么"）。
- ✅ 只提供本包里标记 ✅ 的文件 + `复制给新会话的提示词.md`（整文件复制）。
- ✅ 轮与轮之间只让模型重复提示词（换 `{{N}}`），不要补充任何总结或提示。
- 这四个模型的 `provenance` 已做脱敏（`withheld-for-blind-review`），
  评审模型不会知道每个模型由哪个模型生成、是否人工构建，避免自偏好或"人工=正确"的锚定。
- ⚠️ 同一会话连续三轮存在**自我锚定**（第 2、3 轮看得见前面轮次的输出），这是与 A/B 一致的已知局限，
  论文中如实标注；不影响 C vs B 的"上下文污染"主对照（该对照的唯一变量仍是"读过 A 结果与否"）。
